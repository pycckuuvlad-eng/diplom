Уведомления реализованы с использованием WorkManager для планирования напоминаний. За один час до начала занятия система отправляет push-уведомление пользователю. Уведомление о подтверждении записи отправляется сразу после успешного сохранения данных.

\subsection{Детальное описание алгоритмов работы модулей}

\subsubsection{Алгоритм регистрации пользователя}

Процесс регистрации нового пользователя включает следующие этапы. Пользователь вводит имя, адрес электронной почты, пароль и выбирает уровень подготовки из выпадающего списка (начинающий, средний, продвинутый). После нажатия кнопки «Зарегистрироваться» система выполняет валидацию введённых данных: проверяется корректность адреса электронной почты (наличие символа @ и точки в доменной части), длина пароля (не менее 6 символов), заполненность поля имени. Если валидация пройдена успешно, система проверяет наличие пользователя с таким же адресом электронной почты в SharedPreferences. При отсутствии дубликата данные сохраняются, и выполняется автоматический вход в приложение. В случае обнаружения дубликата пользователю отображается сообщение «Пользователь с таким email уже существует». При нарушении правил валидации система подсвечивает некорректные поля и отображает соответствующее сообщение об ошибке.

\subsubsection{Алгоритм фильтрации занятий по городу}

Фильтрация занятий реализована на клиентской стороне без дополнительных обращений к хранилищу. При загрузке приложения все занятия считываются из SharedPreferences один раз и сохраняются в памяти. При выборе пользователем города из выпадающего списка система последовательно перебирает все занятия и сравнивает значение поля «город» каждого занятия с выбранным значением. Занятия, не соответствующие критерию, исключаются из результирующего списка. После завершения фильтрации адаптер RecyclerView обновляется, и на экране отображаются только занятия выбранного города. Такой подход минимизирует количество операций чтения из SharedPreferences и обеспечивает мгновенный отклик интерфейса.

\subsubsection{Алгоритм записи на занятие}

Алгоритм записи на занятие реализован следующим образом. При нажатии пользователем кнопки «Записаться» система сначала проверяет, не записан ли уже пользователь на данное занятие. Для этого выполняется поиск записи с соответствующими идентификаторами пользователя и занятия в SharedPreferences. Если запись уже существует, пользователю отображается сообщение «Вы уже записаны на это занятие», и процесс завершается. Если запись отсутствует, система проверяет наличие свободных мест. Значение текущего количества участников сравнивается с максимально допустимым. Если текущее количество меньше максимального, создаётся новая запись с уникальным идентификатором, датой и временем создания, а также статусом «активна». После сохранения записи количество свободных мест уменьшается на единицу, пользователь получает уведомление о подтверждении, а кнопка «Записаться» становится неактивной. Если свободные места отсутствуют, пользователю отображается сообщение «Нет свободных мест».

\subsubsection{Алгоритм расчёта прогресса и построения графиков}

Расчёт прогресса пользователя выполняется на основе истории посещённых занятий. После каждого занятия, на котором пользователь отметил посещение, в SharedPreferences сохраняется запись с датой, длительностью занятия и типом практики. При открытии раздела «Прогресс» система извлекает все записи посещений за весь период. Для построения графика посещений по месяцам данные группируются по календарным месяцам: для каждой записи извлекается месяц, количество посещений в каждом месяце суммируется. Полученные пары (месяц, количество) преобразуются в формат, пригодный для отображения библиотекой MPAndroidChart. По оси X отображаются месяцы, по оси Y — количество занятий. Линейный график строится с использованием LineDataSet, который автоматически вычисляет оптимальные интервалы и масштаб. Дополнительно рассчитываются общие показатели: суммарное количество занятий за всё время и общая продолжительность практики в минутах.

\subsubsection{Алгоритм планирования напоминаний}

Напоминания о предстоящих занятиях реализованы с использованием AlarmManager и WorkManager. При успешной записи на занятие система извлекает дату и время начала занятия из соответствующего объекта. Рассчитывается время отправки напоминания — за один час до начала занятия. AlarmManager планирует отложенную задачу (PendingIntent), которая будет выполнена в указанное время. При наступлении запланированного времени система запускает BroadcastReceiver, который формирует и отображает push-уведомление. В случае, если устройство было выключено в момент запланированного времени, WorkManager гарантирует выполнение задачи после включения устройства. Для корректной работы уведомлений приложение запрашивает разрешение POST\_NOTIFICATIONS на устройствах с Android 13 и выше.
